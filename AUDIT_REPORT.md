**Repository:** `defence_anc` (PS26052 — AI/ML Adaptive Noise Cancellation, DRDO/SIH 2026)
**Stack (inferred):** Python 3.9 / NumPy / SciPy / PyTorch 2.5.1 / torchaudio / DeepFilterNet 0.5.6 / soundfile / numba; packaging via `uv` (`pyproject.toml` + `uv.lock`). No web/API/frontend layer exists.
**Audit mode:** Full-tree pass. No source files were modified.

- Total issues found: **27**
- Critical: **0** | High: **1** | Medium: **15** | Low: **11**
- Files scanned: **36** (all 30 Python source files, all config/docs/manifests, lockfile spot-checks, result CSVs verified statistically) | Files skipped: **4 groups**, with reasons:
  - `.venv/**`, `**/__pycache__/*.pyc` — vendored environment / generated bytecode

**Overall health assessment.** The core science is in better shape than the surrounding engineering: the DSP implementations (NLMS kernel, decision-directed Wiener filter, spectral subtraction) are genuine first-principles implementations matching their documented formulations, the seed-based noise-alignment replication between the mixer and NLMS is currently *exact* (verified draw-by-draw against `mix_dataset.py`), and headline artifacts are internally consistent (1,500 eval rows = 300 mixtures × 5 methods; summary table matches raw CSV aggregates; lockfile matches manifest). However, the repo has serious operational fragility: **most of the project's own source code is not under version control**, the PESQ bootstrap path cannot run on any fresh machine, several metric edge cases silently backfill fabricated values in tension with the project's own anti-fabrication rules, and there is no automated test, lint, or CI infrastructure of any kind. No classic security vulnerabilities exist (offline research scripts, no secrets committed, no injection surface); the only network exposure is unverified dataset downloads.

### [ISSUE-003] Duplicate glob causes double processing; self-test enhances the entire mixtures directory including clean references

- **Severity**: Medium
- **Category**: Correctness & Logic Bugs
- **File(s)**: `models/deepfilternet/run_inference.py:37` and `run_inference.py:122-131`
- **Description**: Two related defects. (1) `glob.glob(os.path.join(input_dir, "*.wav")) + glob.glob(os.path.join(input_dir, "**", "*.wav"), recursive=True)` — with `recursive=True`, `**/` also matches zero directories, so every top-level wav appears **twice** in `wav_files`; each file is enhanced twice and the "Enhanced N file(s)" count doubles. (2) `run_self_test()` points at `input_dir=data/mixtures`, which contains both `mix_*` and `clean_ref_*` files, so a self-test sweeps ~600 files (×2 due to bug 1) instead of processing one sample.
- **Evidence**: Line 37 expression quoted above; Python glob semantics: `**` matches zero or more directories when `recursive=True`. On-disk confirmation that `data/mixtures/` holds 300 `mix_*` + 300 `clean_ref_*` files.
- **Suggested fix**: Keep only the recursive glob (deduplicate via `sorted(set(wav_files))`); make `run_self_test()` synthesize its own single scratch wav instead of pointing at the whole dataset directory.
- **Risk if unfixed**: Doubled inference time and misleading counts wherever `batch_inference()` is used (the natural Phase 5 demo path); the self-test takes minutes and pollutes `results/test_enhanced/`.
- **Effort estimate**: Small

### [ISSUE-009] Spectral-subtraction floor deviates from the cited Berouti formulation

- **Severity**: Medium
- **Category**: Correctness & Logic Bugs (methodology fidelity)
- **File(s)**: `baselines/spectral_subtraction/spectral_subtraction.py:57-60`; documented identically in `docs/phase_3_summary.md:24`
- **Description**: The implementation floors at `β·|Y|²` (noisy-signal power) whereas Berouti et al.'s over-subtraction-with-floor formulation floors at `β·|N̂|²` (noise-spectrum power). The variant suppresses noise-dominant bins more aggressively than the textbook method. Code and phase-3 doc agree with each other, but the algorithm is attributed as "Berouti et al." — which the project's own Rule 17 ("genuine implementations of their named textbook algorithm, verified against the standard formula") puts in scope.
- **Evidence**: `floor_power = beta * (magnitude**2)` where `magnitude` is the noisy spectrum; classic floor is relative to `noise_mag_spec**2`.
- **Suggested fix**: Either switch the floor to `beta * (noise_mag_spec**2)` and re-run Phases 3–4 (~36 s total runtime), or keep the variant and amend docstrings/`phase_3_summary.md` to name it explicitly as a modified Berouti floor with rationale.
- **Risk if unfixed**: Baseline comparison numbers may misrepresent the classical method in the DRDO-facing write-up.
- **Effort estimate**: Small (fix) / Trivial (document)

### [ISSUE-021] Peak-protection scaling applied to enhanced outputs is not part of the metric contract

## Cross-Cutting Observations

1. **Silent exception swallowing is a recurring idiom** — bare/broad `except Exception: pass` blocks in `mix_dataset.py:107-110`, `benchmark_rtf.py:26-27,34-35`, download progress hooks, etc. Mostly benign here, but collectively they contradict the project's own Rule 4 ("do not silently retry-and-hide").
2. **All evidence lives in stdout + hand-transcribed progress.md quotes.** No module uses `logging`; exclusion lists, ablation tables, and sanity-check results exist only transiently (see ISSUE-017). Durable machine-readable evidence files would close the loop between "command was run" and "output can be re-examined."
3. **The batch-processor template is genuinely good and consistently applied** — all four batch runners implement manifest iteration, idempotent skip-if-exists (Rule 20 ✓), pilot timing (Rule 19 ✓), and peak protection. Weaknesses are cosmetic (ISSUE-027) rather than structural.
4. **Performance posture is healthy.** The numba-JIT O(N·L) NLMS kernel, vectorized STFT pipelines, and measured throughput show no N+1 patterns, no sync-I/O-on-hot-path problems, and no unbounded memory growth. This category is otherwise clean.
5. **Security posture is clean apart from supply-chain hygiene.** No secrets committed, no `eval`/`exec`, no deserialization of untrusted data, no web surface, subprocess use is fixed-argument-list only. The single exposure class is unverified network downloads (ISSUE-014).
6. **Documentation strength is well above hackathon average** — `data/SOURCES.md` licensing/proxy audit and per-phase summaries with verbatim command evidence are exemplary; remaining gaps are precision (ISSUE-015), schema drift (ISSUE-022), and the absent README recipe (ISSUE-016).
7. **Accessibility & i18n: not applicable** — no frontend/UI code exists in the repository.
