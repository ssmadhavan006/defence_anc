# requirements-optional.txt
# PS26052 — OPTIONAL extras, deliberately kept OUT of requirements.txt.
#
# Nothing here is needed to run the live audio pipeline or the demo. This
# file exists so that a dependency-resolution failure in an optional feature
# can never block the demo path (which is exactly what happened on the Pi
# 2026-08-24: adding scipy to requirements.txt made the whole file
# uninstallable with ResolutionImpossible, taking the core pipeline install
# down with it).
#
# Install only if you need the specific feature noted:
#   pip install -r requirements-optional.txt

# --- P1-1 residual filter (live/residual_filter.py) ---
# Only needed if you set pipeline.residual_filter: true in
# config/audio_config.yaml. That feature is OFF by default and has not yet
# been quality-validated (no PESQ/STOI A/B run) -- see the module docstring.
# The pipeline imports it lazily, so its absence does not affect the default
# configuration at all.
# numba 0.67.0 verified: has a cp313/aarch64 wheel AND allows numpy<2.6,
# so it coexists with the numpy==1.26.4 pin deepfilternet requires.
numba==0.67.0

# --- P1-4 dataset augmentation (data/augment.py) ---
# NOT required: data/augment.py implements its own numpy FFT convolution and
# has no scipy dependency (verified numerically identical to
# scipy.signal.fftconvolve in its self-test). scipy is listed here ONLY
# because augment.py's self-test will cross-check against it when present.
#
# Pin rationale: scipy>=1.18 requires numpy>=2.0.0, which is INCOMPATIBLE
# with deepfilternet's numpy<2.0. scipy 1.17.0 (numpy<2.7,>=1.26.4) is the
# newest release that still works with the numpy==1.26.4 pin and has a
# cp313/aarch64 wheel. Do not loosen this without re-checking that.
scipy==1.17.0

# --- P1-3 ONNX Runtime backend (models/deepfilternet/export_onnx.py) ---
# ⚠️ KNOWN INCOMPATIBLE ON PYTHON 3.13 (the Pi's version). Do not expect
# these to install alongside deepfilternet there.
#
# Verified against PyPI metadata 2026-08-24: `onnx` requires `ml_dtypes`,
# and EVERY published ml_dtypes release (0.5.0 through 0.6.0) declares
# `numpy>=2.1.0; python_version >= "3.13"`. deepfilternet requires
# numpy<2.0. On Python 3.13 those are mutually exclusive -- there is no
# version combination that satisfies both, so the ONNX backend cannot run
# on the Pi's current environment. This is a hard upstream constraint, not
# a pinning problem.
#
# The ONNX backend remains fully functional on Python 3.11/3.12 environments
# (verified working and bit-exact on the dev machine, Python 3.11), and
# pipeline.inference_backend defaults to "pytorch", so this affects nothing
# in the default configuration. Revisit if deepfilternet gains numpy 2.x
# support, or run the Pi on Python 3.12.
onnx>=1.22.0
onnxruntime>=1.29.0
# Needed even though export_onnx.py never uses torch's dynamo exporter: on
# newer torch releases (confirmed: the Pi's), torch.onnx.export() imports
# dynamo exporter machinery internally regardless of which path runs.
onnxscript>=0.7.1

# --- P4-1 WOW #2: web dashboard (demo/webdash/) ---
# FastAPI + Uvicorn serve live telemetry and /mode/{enhance|bypass} over LAN.
# Not in requirements.txt: a resolution failure here cannot block the demo
# path (same policy as scipy -- the core pipeline is unaffected when the
# webdash is not started, same as the dashboard is a separate process).
#
# Pin rationale:
#   fastapi>=0.100: first release that dropped Python<3.8; stable REST/WS API.
#   uvicorn[standard]: the [standard] extra bundles websockets and httptools
#     required for WebSocket support; not a separate package.
#   qrcode[pil]: [pil] is the Pillow extra needed to write image files. Pillow
#     is also pulled in by deepfilternet on many installs, so usually free.
# All three have cp313/aarch64 wheels (Pi-compatible).
fastapi>=0.100.0
uvicorn[standard]>=0.20.0
qrcode[pil]>=7.4

# --- P4-2 WOW #3: DNSMOS non-intrusive MOS monitor (models/dnsmos/) ---
# onnxruntime for INFERENCE ONLY -- NOT the P1-3 ONNX export path above.
# Unlike the P1-3 block, this IS Pi-compatible: onnxruntime inference has no
# dependency on `onnx` or `ml_dtypes`, so the numpy<2.0/numpy>=2.1 conflict
# on Python 3.13 never triggers (verified against PyPI metadata 2026-09-04;
# see phase4_plan.md §1.2 for the full analysis).
#
# VERSION STRATEGY (D3-A, phase4_plan.md §4):
#   Dev machine (Python 3.9.25): onnxruntime==1.18.0
#     Last release to publish a cp39 wheel; 1.19.0 dropped Python 3.9.
#   Pi (Python 3.13):            onnxruntime>=1.18.0
#     1.29.0 verified compatible; manylinux_2_17_aarch64 wheel available.
# ONNX model format and InferenceSession API are stable across 1.18→1.29.
# Timing numbers from the dev machine are dev-machine numbers only (Rule 5).
#
# Do NOT install this alongside the P1-3 onnxruntime line in one pip call;
# they share the same package name. Install the right version separately:
#   Python 3.9 (dev):   pip install onnxruntime==1.18.0
#   Python 3.13 (Pi):   pip install "onnxruntime>=1.18.0"

# --- Dashboard rebuild (2026-09-05): reference-replay Mode 2 + Record & Compare ---
# live/stage_metrics.py imports eval/metrics.py's compute_stoi/compute_pesq_wb,
# which need pystoi/pesq (guarded at CALL time, not import time, so a missing
# package degrades that one metric to None with a one-time stderr warning --
# see live/stage_metrics.py's _warn_missing_dep_once -- rather than crashing).
# demo/webdash/record_compare.py imports baselines/spectral_subtraction and
# baselines/wiener directly, which need `scipy` -- already pinned above
# (scipy==1.17.0) for the P1-4 augmentation section; no new scipy line needed.
#
# pystoi: pure Python, universal wheel, no compiler needed. Low risk.
pystoi>=0.4.1
#
# pesq: PyPI publishes ONLY a source sdist (verified 2026-09-05, no wheel for
# ANY platform) -- it's a C extension, always built from source. Needs a C
# compiler; Raspberry Pi OS may not have one by default:
#   sudo apt install -y build-essential
# ⚠️ NOT YET VERIFIED ON THIS PI'S aarch64/Python 3.13 (Rule 29) -- if the
# build fails, reference-replay's PESQ-WB cell degrades to None (the
# _warn_missing_dep_once warning above) while SI-SNR/STOI keep working; it is
# not a blocker for the rest of the dashboard.
pesq>=0.0.4
#
# httpx: only needed to run this project's own --self-test suites for
# webdash/compare/record_compare (starlette.testclient's TestClient uses it).
# NOT needed at runtime -- skip this line if you only intend to run the demo,
# not `python scripts/run_all_selftests.py`, on the Pi.
httpx>=0.28.1
