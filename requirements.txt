# deepfilternet 0.5.6 hard-requires numpy<2.0. It is NOT listed in this file
# (assumed pre-installed, see above), so pip's resolver cannot see that
# constraint and will happily install numpy 2.x to satisfy some other
# package, silently breaking deepfilternet -- this happened on the Pi
# 2026-08-24 (numpy 1.26.4 -> 2.5.2, with pip printing a dependency-conflict
# warning but installing anyway).
#
# EXACT pin, not a range: an open range (numpy>=1.22.0,<2.0) let pip's
# backtracking resolver wander into older numpy patch versions while jointly
# resolving with other packages, even though 1.26.4 already satisfied
# everything and was found first -- it ended up trying to BUILD numpy 1.25.2
# from source (no aarch64 wheel for that patch) and failing on Python 3.13
# (pkg_resources/setuptools: `pkgutil.ImpImporter` was removed). An exact pin
# removes numpy as a backtracking axis entirely. 1.26.4 has a prebuilt
# cp313/aarch64 wheel and is the version the Pi already runs.
numpy==1.26.4
